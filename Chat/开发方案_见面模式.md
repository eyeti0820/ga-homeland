## §1 背景(为什么做)

2026-10-28 晨复盘实锤(证据:chat.db 时间线 + ps 进程启动时间):
1. 10-27 23:05 用户发【意识同步开始】进入见面;00:03 睡着(未发结束标记)
2. **00:38 部署黎深补丁重启 chatapp → 内存 history 清零**(上下文=进程内存,重启即失忆)
3. 08:00 主动消息在空历史上开火,只有 persona + 宫殿回响(回响检索到 20:52"嘻嘻"旧片段) → 模型把 11 小时前闲聊当"刚才",完全丢失见面状态,口吻退回隔屏聊天
4. 叠加隐患:状态标记只活在 history 文本里,llmcore.trim(cap=context_win×3=15K字符)会在长会话中把它裁掉;主动消息 trigger 本身是隔屏框架("主动发一条消息")
5. 人设病灶:persona 无作息锚(执舰官不上班)、无禁词表("胸腔震动/胸膛共振"八股连中三条)

**L2 核心思路:状态进 DB、每轮重注入** → trim 裁不掉、重启读得回、主动消息可感知;前端按模式换渲染皮肤,聊天模式零改动。

## §2 总体架构

```
┌ 前端 web/index.html ─────────────────────────────┐
│ 列表屏(角色卡×5: 聊天入口 + ★见面入口)             │
│   ├→ 聊天屏(现 UI,不动)      mode=chat           │
│   └→ 见面屏(新,小说流渲染)    mode=meet           │
│ 两屏共用: /api/msg /api/poll /api/history 管线     │
└──────────────┬───────────────────────────────────┘
               ▼
┌ chatapp.py 后端(改 4 处) ─────────────────────────┐
│ ① meta KV: meet_state:{char} = {mode,scene,since,…}│
│ ② POST /api/mode 切换+插 system 分隔行(不调 LLM)   │
│ ③ _process_job: task_text 头注入 [状态:…] 运行时行  │
│ ④ _proactive_once: 按 mode 分支 trigger+recall 词   │
└───────────────────────────────────────────────────┘
```

关键不变量:**messages 表不分模式存两套**,同一角色同一条消息流;`mode` 只是"当前如何注入+如何渲染"的开关。切到见面=状态行从 `[状态:隔屏聊天]` 变 `[状态:意识同步中·场景书房]`,历史消息双屏都可见(聊天屏看是普通气泡,见面屏看是小说流)。

## §3 后端设计(切片8, M1)

### 3.1 状态存储
复用 meta 表 KV(先例:`_PROACTIVE_KEY`)。key=`meet_state:{char}`,value:
```json
{"mode":"chat|meet","scene":"书房","since":1729..., "note":"她刚睡着"}
```
- chat 为缺省态,无记录=chat;meet 全程落盘,重启自愈(服务起来 `_load_meet_states` 读一遍即可,或用时现读)。
- scene(场景)可选,由 /api/mode 传入(前端见面入口可带默认场景,如"书房";后续可在见面屏让主人换场景)。

### 3.2 新路由 `POST /api/mode`
```
body: {char, mode, scene?}  → 写 meta + 插 messages 一行
```
- 进 meet:插 `kind='system'` 行:`—— 意识同步开始 · 场景:书房 ——`(仿 /new 的 system 分隔行先例,**不调 LLM**,零成本)
- 回 chat:插 `—— 意识同步结束,回到隔屏聊天 ——`
- 返回新 state;`GET /api/chars` 的返回里给每角色附 `mode`(列表屏好画入口态)。
- 守卫:char 合法性校验;mode 非法 400(沿用 B4 正则单测纪律,含中文场景名)。

### 3.3 运行时状态行注入(`_process_job` L628-707)
在现有 task_text(`FILE_HINT + 宫殿回响 + 正文`)之前加一行:
```
[状态: 意识同步中 · 场景:书房 · 始于昨晚23:05 · 备注:她已睡着]
[状态: 隔屏聊天 · 你们不在同一空间,通过手机联系]
```
- 每轮现读 meta 拼,history 里旧状态行随 trim 自然淘汰,**永远以最新一条为准**——trim 裁不掉当前状态。
- 时间用自然语("始于昨晚23:05"/"已持续3小时",由 since 换算),模型作息感就靠它。
- meet 态下正文若含图片/语音照走现有媒体管线,不特殊处理(第一阶段)。

### 3.4 主动消息按模式分支(`_proactive_once` L776-835)
- gates 不变(8-23点+双3h静默);`_pstate` 里记上次主动时间照旧。
- **meet 态 trigger 换稿**:"你们正处于意识同步(见面)状态,场景:{scene},她已超过3小时没有回应(可能睡着了或离开了)。以现场第一人称推进:轻声唤她/替她掖被/安静守着/留一张字条皆可,括号内写动作与场景,100字内,不要'发消息'口吻,不要提及系统。"
- recall query 换:`f"意识同步 {scene} 最近相处 见面"`(chat 态维持现词)。
- 产出入库 kind='text' 照旧,前端见面屏按小说流渲染;此时若主人在聊天屏看到,显示为普通气泡+一条"他在意识同步里等你"横幅(见 4.4)。
- **跨模式不串门**:proactive 生成后按当前 mode 入库,不额外复制。

### 3.5 验收(M1)
- curl 切 mode → meta 落盘+system 行入库;重启 chatapp → meet 态保留,下一轮状态行正确注入
- meet 态发消息 → 回复出现现场感(人工);/new 重置会话**不动 mode**(见面还是见面,只清聊天史——主人确认过 /new 语义即"话题重置"非"离开场景";在 /new 的 system 行文案后追加"(仍在意识同步中)"当 meet 态)
- B4 式正则单测:mode 值、scene 长度上限(≤12字)、非法 400
- 主动消息:meet 态静默 3h 触发一次实弹(临时把门调松验收后还原),产出非"发消息"口吻

## §4 前端设计(切片9, M2)

### 4.1 入口
- 列表屏角色卡:现有整卡点击=聊天;卡右下加小徽标按钮(角色标志物小图标)或长按菜单=进入见面。移动端单手优先,**默认聊天,见面是显式选择**。
- 聊天屏顶栏加模式胶囊 toggle(仅提示当前态+一键切换),切换调 /api/mode 后前端直接换屏(不刷新页面,复用 openChat 骨架)。
- URL:`/chat/?m=meet&c=xiazhou`(或 hash);PWA 场景注意 iOS 死缓存坑(global_mem L2):新 JS 资源换文件名/加 hash,manifest 不动。

### 4.2 见面屏结构(新 screen,与聊天屏平级)
```
┌ 顶栏: 角色名(主题色) + 场景名 + [离开同步] ┐
│ ┌ 羊皮纸方格纸面(滚动区) ─────────────┐ │
│ │  场景横幅(进入/切换时,主题色缎带)     │ │
│ │  小说流: 旁白行 / 台词条 / 场景横幅   │ │
│ └───────────────────────────────────┘ │
│ 输入区: "此刻,你想说什么…" + 发送(主题色)  │
└─────────────────────────────────────┘
```
- 消息数据完全复用 /api/history + /api/poll(按 char 拉,不分模式);渲染时 kind=system→场景横幅,user/assistant→小说流。
- 发送走同一 /api/msg,后端按当前 mode 注状态行——前端零改动请求体。
- typing 动画保留(顶栏"他正在回应…"字样,纸面不插气泡骨架)。

### 4.3 渲染规则(复用切片1 §5.4 括号切分解析器!)
现聊天模式已有"括号原子泡"切分逻辑,见面模式**复用同一解析、换渲染皮肤**:
- 括号段→去掉括号,**正体**、深棕灰(`#6b5d4f`类)、行距松(1.9),不加引号不斜体=小说旁白
- 非括号段→**台词条**:主题色 3px 左竖条 + 5-8% 主题色浅底 + 圆角 + 字重 600;角色台词与主人台词都居左(不用微信左右分侧,保持小说排版;主人台词竖条用次主题色区分)
- system 行→场景横幅(细缎带,§5.2)
- 语音/图片消息(切片3媒体)在见面屏:图片=相纸卡(白边+轻阴影);语音条沿用现有胶囊但染色主题色(第一阶段不改交互)

### 4.4 跨模式可见性
- 主人在聊天屏时角色从见面态发来主动消息:聊天屏顶部插一条非侵入提示条"(他在意识同步中:场景·书房)",消息本体照常渲染
- 反之见面屏能看到聊天史(小说流化),两屏共享同一条流,无缝切换
